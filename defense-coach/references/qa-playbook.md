# 答辩问答手册

## 应答三句式

```
① 承认事实（不解释客观困难）
② 定位问题等级（这是核心缺陷 / 这是次要问题 / 这是取舍结果）
③ 给出改进方向（下一步会怎么做）
```

范例（被问"续航只有 12 小时，对你们的场景够吗？"）：

> "续航确实是我们没有花太大精力解决的部分。它是这个项目最致命的短板。如果还有时间，我们会优先换更高能量密度的电池并重做功耗预算。"

三句话，不超过 20 秒。不甩锅队友，不解释"因为时间不够"，不反问评委。

## 三条禁令

| 禁令 | 为什么 |
|---|---|
| **不要绕** | 你绕不过去。评委问的是 A，你答 B，他会再问一遍 A，且分数已扣 |
| **不要沉默** | 沉默在答辩场上等于弃权。哪怕只答"这部分我们没做，是下一个阶段的工作" |
| **不要辩** | 除非评委记错事实。辩赢＝当众证明他错，收益为负；辩输＝双输 |

**唯一可以辩的情形**：评委陈述的事实与你做的客观不符（"你们用的是钠电池吧"——实际是磷酸铁锂）。此时也只说一句"我们用的是磷酸铁锂，参数在第 6 页"，不延伸、不纠正他的判断、不评价他的记忆。

## 五类高频问题与准备方式

| 类型 | 典型问法 | 准备方式 |
|---|---|---|
| **概念** | "你这个 XX 和 YY 有什么区别？" | 每个核心术语准备一句定义 + 一个类比；准备"上下游三个概念"的辨析 |
| **方法** | "为什么用 A 不用 B？" | 给三条理由：精度/成本/可解释性；再给一句"B 在我们场景下的具体问题" |
| **数据** | "这个数字怎么来的？样本多大？" | 记住关键数字的来源、样本量、实验条件；不确定就说"这个数我需要回去核对" |
| **缺陷** | "这个方案最大的问题是什么？" | **主动准备**：自己先说最大缺陷，比被问出来好得多 |
| **动机** | "为什么做这个？有什么价值？" | 一句"谁在什么场景下会用它"，不要说"因为感兴趣" |

## 通用准备动作

1. 写 15–20 个预测问题，按上面五类归档
2. 每题写三句式答案，控制在 3 句内
3. 标记"答不上来"的 3 个，准备诚实话术："这部分我们确实没深入，目前只知道 X，回去会补"
4. 找一个人对着问一遍，只记录"你绕了几次"

## 心态脚本

上场前默念（不是话术，是状态）：

> "我就做了这么点东西，在各位眼里可能一般，但我尽力了，我做的东西在我眼里还不错。我今天来就是把它讲给你们听。"

它的作用不是自我催眠，是把注意力从"我会不会被看穿"转到"我要把这件事讲清楚"。前者让你加速、抢话、绕圈；后者让你正常输出。

**先自己信，才能让别人信。** 这不是让你假装项目很牛，是把已有事实重新组织到"我自己也认"的程度——比如"暑假自学了从线性回归到 Transformer 的底层原理并手撸了几个项目"，这是事实，只是很多人不敢这么组织语言。

## 作品未定型时怎么打

如果只有方案、没有结果（大创开题、早期竞赛），主线换成：

```
真实痛点（有数据）→ 现有方案的具体缺陷（逐条）→ 我们的切入点（为什么这个角度没人做）
→ 已完成的前期验证（哪怕是仿真/小样本）→ 下一步计划与里程碑
```

关键：**把"没做完"讲成"分阶段"，把"没有结果"讲成"有验证路径"**。评委能接受阶段成果，不能接受"我们打算做"却说不出第一步怎么验证。

## 常见扣分点

- 超时（最冤，且最常见）——排练时按 90% 时长准备
- 全程看屏幕/背对评委
- 前 30 秒讲团队介绍、指导老师致谢（评委不关心）
- 结论页写成"感谢聆听"
- 被问住后开始解释"因为我们时间不够/队友不给力"
